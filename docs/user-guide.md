# 多模态毫米点云使用手册

新增直接计算入口：**测量复核 → 几何特征与剖面序列**。支持沿拟合中心线的局部法向剖面、G/T 特征、缺失及复核掩码和批量导出；公式、字段、参数与限制见 [几何特征说明](features.md)。左侧卡片只显示点云清理、坐标对齐和测量复核三项状态，测量进度与右侧剖面序列一致。

测量复核面板在桌面上按“上方参数、中间并列序列曲线与剖面、区域批量操作、下方整行几何指标”排列，窄屏自动调整布局。端点与地面默认沿用已确认对齐，不再另外选择参考条件。右侧三个单独下载按钮已移除，整体几何特征与剖面序列从顶部“导出点云成果”一起保存。序列曲线下拉框可切换全部 10 个通道，包括“可见横剖面弧长”。该弧长沿横向分箱中位数折线累计，存在缺箱、稀疏箱或明显高度跳变时留空，具体原因显示在当前片信息中。它与前后方向的中心线弧长、横向投影宽度分别记录，不代表完整围度。新导出的 CSV/NPZ 为 v2 格式，默认 32×10，读取时使用通道名。

本文由原项目 README 整理而来。启动与文档导航见 [项目首页](../README.md)，代码位置见 [目录与文件职责](project-structure.md)，迭代记录见 [变更日志](CHANGELOG.md)。下文原命令仍从科研工作区执行。

支持双目（Gemini 336L）和 iToF（Femto Bolt）相机，各自可读取 IR 或 RGB 分割，生成**以原始深度相机为原点、单位毫米的可见表面点云**。点的坐标保持实际尺度，不居中、不对每头猪归一化。每次采集独立输出。

这里的“生成”是有标定约束的测量重建，没有新增或训练生成模型，没有补全遮挡身体。工作台按用户选择的采集与分割目录载入数据，不合并不同时间、不同姿态或不同相机的数据。

## 浏览器工作台（推荐）

macOS 双击 **启动点云工作台.command**（原来的 **打开点云预览.command** 也会进入新工作台）；Windows 双击 **启动点云工作台.bat**。程序启动本机服务并打开浏览器，使用期间保留终端窗口。默认地址是 `http://127.0.0.1:8769`。

Windows 可从中文或带空格的项目路径启动；也可在 PowerShell 使用 `python app.py --open`。根目录 bat 与 `scripts/` 中的 bat 支持 `--port` 和 `--state` 参数。重新启动时，同版本服务会复用；代码更新后会重启空闲服务，任务尚未完成则显示原因，请等待任务结束。依赖请安装在当前 Python 环境，无需另外复制分割程序或 macOS 的 `.deps` 文件夹。

1. 点击顶部“目录设置”（或路径摘要），在弹窗中选择**原始采集目录**，即包含 `pig_编号/采集时间/` 的根目录。
2. 选择**分割结果目录**，即包含 `dataset.json` 的分割成果根目录。点击“核对并载入目录”，页面显示匹配、确认和缺失文件情况。输入搬到其他磁盘或 Windows 后，按相对目录重新匹配，不依赖旧的绝对路径。
3. 选择**导出目录**，填写新的成果文件夹名。
4. 勾选采集，点击“生成并按文件夹导出”。默认只生成已确认分割；试跑初稿需明确勾选“允许初稿预览”。页面显示逐项进度、跳过及失败原因，可在完成当前采集后停止。
5. 对已有点云，点击顶部“导出点云成果”或“导出本条”，分别勾选点云清理／坐标对齐／测量复核，再选择采集范围、各阶段保留／待定／淘汰状态、保存目录及成果名。已完成的阶段可单独或合并导出，后序未处理不影响前序；前序淘汰停止后序。测量的 JSON／CSV／NPZ 自动随成果保存，导出前显示各阶段数量，可在上方修改保存目录和成果名。

界面使用浅色主题，点云画布为浅灰网格。左侧可按记录中的相机类型（iToF／双目）和分割来源（RGB／IR）独立筛选，并显示各类采集数；未知相机单独列出，不根据目录名猜测。未勾选采集时，生成范围限定为当前筛选结果；有明确勾选时处理全部已勾选项，筛选外的勾选数量会在左上角提示。

左侧阶段筛选只保留五项：**全部采集、清理已确认、清理与对齐已确认、三阶段已完成、已跳过**。阶段条件逐级累加，例如“三阶段已完成”的采集也属于“清理已确认”和“清理与对齐已确认”。确认表示相应阶段的当前版本有成果且已明确保留；待定、淘汰、被前序阻断或版本失效不算确认。搜索、相机和分割来源仍可叠加，切换工作页签不改变筛选范围；已跳过只查看手动标记跳过的采集。

三阶段进度、各阶段确认数和当前筛选内完成数移至左栏顶部。点击 **收起筛选／展开筛选** 可隐藏或显示搜索、相机、分割来源、阶段筛选和核对入口；收起后显示当前条件摘要，原条件及已勾选采集保留，并记住展开状态。列表与勾选操作始终可用，进度不会盖住列表或点云。每条采集继续显示完成状态，逐片测量复核进度单独保留。

顶部只保留操作按钮和当前路径摘要，把空间留给点云。生成提示和完成消息集中在底栏，点击底栏“详情”查看进度、停止操作以及跳过／失败原因，任务完成后不会新增顶部信息行。右侧在一屏内显示点数、有效率、毫米坐标范围和检查图，详细来源和提醒点击“复核提醒”查看；左侧采集列表独立滚动。服务重启后，目录选择等请求会自动更新会话并重试一次；目录或数据集已改变时仍会要求重新载入，避免使用旧采集状态生成。

所有目录按钮（包括“打开已有点云目录”）都通过本机服务打开操作系统原生目录窗口：macOS 使用 NSOpenPanel，Windows 使用 IFileOpenDialog 目录模式。取消选择会保留原路径。也可直接填写路径。换电脑后需在该电脑启动服务，窗口会出现在运行服务的电脑上。

导出已有成果时，选择“按阶段拆分文件夹”可保存各阶段精简成果，选择“按采集合并存放”可保存含原始文件、处理记录和离线预览的完整副本。两种方式均写入选定的本地文件夹，保留 `pig_编号/采集时间/` 层级，不需要逐个下载文件。目标同名目录已存在时要求换名，避免覆盖。正式分割和原始采集保持只读。完成后可点击“在系统中打开成果文件夹”。

Windows 首次运行前安装 Python 3，并在科研目录执行：

```sh
py -3 -m pip install -r pointcloud_workbench/requirements.txt
```

也可手动启动：

```sh
python3 pointcloud_workbench/app.py --open
```

## 已有预览

首次启动工作台会自动载入已有示例，也可点击“打开已有点云目录”选择其他完整结果。生成及合并导出的 `index.html` 和逐帧 `preview.html` 可直接打开离线查看；阶段精简包的 `index.html` 提供成果文件链接。

首批示例包含耳标 1000 的三次采集，以及 1514、5905 各一次，共五次。结果写在 `outputs/itof_多模态毫米点云预览`。这些掩码在运行时全部为 `reviewed=false`，所有结果均明确标为“未审核初稿 · 流程预览”，没有修改人工复核状态。

页面支持旋转、缩放、正视、侧视，切换 RGB／原始红外强度／深度／RGB 可用性配色。浏览器显示至多 24000 个固定随机种子均匀抽取的预览点，完整导出包含掩码内全部可反投影的有效点。显示为便于旋转使用中心视图，导出数据仍保留相机原点。

## 正式生成

先在 SAM 分割工作台修正边界，记录头侧方向，点击“确认合格并保存”。然后双击 **生成已确认点云.command**，默认只读取 `status=reviewed` 且 `reviewed=true` 对应的 `trunk_mask.png`。

也可从科研工作区执行（下述 `python3` 需具有 NumPy、Pillow、OpenCV）：

```sh
python3 pointcloud_workbench/batch.py \
  --segmentation outputs/itof_SAM2猪体分割 \
  --output outputs/itof_多模态毫米点云
```

当前本机启动脚本自动优先使用 Codex 自带 Python，OpenCV 沿用 `segmentation_workbench/.deps`。换电脑时可安装本目录 `requirements.txt`。

当前没有已确认帧时，正式命令会如实报告跳过数量，生成空的结果索引，不把初稿自动当成合格结果。该步骤不要求先审核完全部图片，确认一张即可生成一张。

只想试跑未审核初稿时，须显式添加 `--allow-draft`，并使用独立预览目录：

```sh
python3 pointcloud_workbench/batch.py \
  --segmentation outputs/itof_SAM2猪体分割 \
  --output outputs/itof_多模态毫米点云预览 \
  --allow-draft --pig 1000
```

`--pig` 与 `--capture` 可重复指定；`--limit` 限制匹配后的采集数量。已有且输入一致的结果会复用。分割修订或原始文件改变时拒绝复用，需指定新的输出目录，以免覆盖先前结果。`summary.json` 是本次运行的统计；`index.html` 会列出该目录内的数据集已生成结果。

## 模态与坐标

相机类型与分割输入是两个独立维度：相机型号从逐帧 `reconstruction.json` 的设备记录读取，
不根据目录名称判断；几何计算使用该帧的实际 profile、深度比例和外参。

|相机|分割输入|主 PLY 文件|默认预览配色|
|---|---|---|---|
|双目|IR|`cloud_ir_mm.ply`|红外强度|
|双目|RGB|`cloud_rgb_mm.ply`|RGB|
|iToF|IR|`cloud_ir_mm.ply`|红外强度|
|iToF|RGB|`cloud_rgb_mm.ply`|RGB|

每次采集只导出与分割输入一致的一种 PLY。IR 路径可在 NPZ 内保留已配准的 RGB 属性用于复核，
预览中切换配色不会生成另一个 PLY，也不改变点坐标。
`pointcloud.json` 记录 `input_mode`、`camera`、`primary_ply` 和 `export_policy`。
旧成果缺少 `input_mode` 的 IR 记录仍可加载；重新导出旧成果时在新目录中只保留主 PLY，
更新预览和导出清单，原成果不变。

### RGB 分割输入（含 Gemini 336L 双目）

工作台也支持当前分割工作台生成的 `input_mode=rgb`、`rgb-aligned-depth-v1` 成果。
程序核对掩码对应的几何标识、源文件校验值、所选帧身份和实际对齐输出 profile，
使用 `depth_aligned_to_color_code_u16.npy` 及其毫米换算系数反投影，
而不是将 1280×720 的 RGB 掩码套在 848×480 的原始深度上或缩放掩码。

RGB 图会按分割时相同的规则映射到保存的对齐深度网格，配色与掩码使用同一网格。
先得到彩色相机坐标，再应用记录的 `depth_to_color` 的逆变换一次，
因此最终 XYZ 仍以原始深度相机为原点、单位毫米。不会再次将已对齐深度执行正向对齐。
`pointcloud.json` 记录变换矩阵和像素坐标系；RGB 路径的 `pixel_uv` 是对齐彩色网格坐标，
`depth_code` 是该网格的彩色相机轴向深度码，不能将其直接解释为导出 XYZ 的 Z。

旧 RGB 分割若没有通过几何核对，程序会明确要求新建 RGB 分割任务。
初稿预览只允许未审核掩码，不会绕过文件、标定、深度单位或几何一致性检查。

本 RGB 路径尚未关联原始红外强度，因此 NPZ 的 `infrared_raw` 为 NaN、
`infrared_valid` 为 false；预览禁用红外配色，也不生成 `cloud_ir_mm.ply`。
旧版 RGB 成果可能包含灰色占位的 `cloud_ir_mm.ply`，工作台仍可加载，灰色不能解释为测得的红外值。
RGB PLY 和 NPZ 保存完整有效几何。

如果采集目录中存在 `depth_sensor_code_u16.npy`，生成时会另行反投影原始深度，
应用该帧的深度到 RGB 外参，再投影到分割所用的对齐网格，与 SDK 保存的对齐深度交叉比较。
全场景和掩码内稳定表面分别记录比较点数、轴向深度差中位数及 95% 分位；
诊断容差为 `max(5 mm, 1% Z)`，满足比例低于 90% 或稳定点不足 100 时提示复核。
深度突变和无效点附近不参与数值比较。此诊断不改变掩码或点坐标，也不自动拟合标定参数。
诊断异常时可查看检查图并标记跳过，不会阻断其他采集；缺少原始深度时明确显示未完成交叉核对。

`pointcloud.json` 的 `rgb_registration` 记录结果，原始深度码也纳入源文件哈希。
右侧“RGB 配准核对”打开原始 RGB 上的独立检查图：青色为按记录标定投影的原始深度边缘，
黄色为经畸变映射回原图的 RGB 掩码边界。两者可用于检查轮廓偏移，但深度边缘不全是猪体边缘。
这只核对记录的几何一致性，不能替代标定板重标定或已知尺寸实物的精度验证。
已有 RGB 结果仍可查看；CLI 不再复用缺少此版本核对记录的旧结果，重新生成需选新的成果目录。

以下表格介绍原生红外分割路径：

|来源|用途|
|---|---|
|`trunk_mask.png` 或显式允许的初稿|选择红外原始像素坐标中的目标区域|
|`depth_sensor_code_u16.npy`|按对应帧 `value_scale_mm_per_code` 还原毫米轴向深度|
|`reconstruction.json` 的实际深度 profile|使用内参及 Brown rational K6 畸变求逆射线；`XYZ=(x_ray Z,y_ray Z,Z)`|
|`infrared.npy`|按原始像素关联 IR 属性；没有称为回波置信度|
|`color.png`、实际彩色 profile、深度到彩色外参|投影到原始 RGB 图配色，保留独立的配色有效标记|

导出的深度相机坐标：X 向右，Y 向下，Z 向前；单位都是 mm。RGB 配色时把点临时变换到彩色相机坐标，不改变导出的 XYZ。该流程使用原始深度，不再对已对齐深度重复应用外参。

原始 Femto Bolt 深度存在畸变，因此没有直接把原始像素套入无畸变针孔公式。使用 OpenCV 迭代求逆，并以独立的 Brown K6 正向投影检查射线，重投影误差超过 0.05 像素时不输出该点。检查收敛仅验证数学一致性，不能替代已知尺寸实物的测量精度验证。

程序检查 IR 与深度的内参、畸变、到彩色相机的外参，以及设备帧号和时间戳；这些记录一致后才允许直接套用掩码。实际图像边界配准仍应查看检查图。当前仅支持记录明确且没有镜像／翻转的图像和 Brown／无畸变模型，未知模型会明确报错。

RGB 与深度默认允许的设备时间戳绝对差为 10000 μs。RGB 分割依赖 RGB 掩码选点，超过时拒绝该采集并继续处理其他采集；IR 分割的几何不依赖 RGB，超过时保留几何、仅将 RGB 属性标为缺失。可用 `--max-rgb-delta-us` 更改阈值。IR 路径关联 RGB 时，空间可见性使用全场景深度投影的 z-buffer 和 3×3 近邻最小深度，默认 20 mm 容差（`--visibility-mm`）；这是稀疏采样下的可见性近似，不能保证识别仅彩色相机看见的遮挡物，也不能弥补猪体运动造成的不同步。

样本记录的深度到彩色矩阵有轻微非正交误差，程序按源记录原样使用并报告，不擅自修正标定。其影响主要需要检查 RGB 边界；原生深度相机 XYZ 没有使用这个矩阵。最终配准质量需结合实际图像验证。

## 点云清理与测量复核

主界面按 **点云清理 → 坐标对齐 → 测量复核** 排列三个步骤。点云查看并入“点云清理”，保留旋转、缩放、视角、取景与坐标系切换；“测量复核”独立显示切片与测量工具。继续沿用左侧采集列表、中间视图、右侧工具的布局，也可隐藏工具扩大视野。

### 保守清理

1. 选择采集，打开 **点云清理**。默认检测“远离主体的点”：以原相机坐标各轴 1%–99% 范围外扩 300 mm，提出候选；这是一项可调的复核规则，不是通用猪体尺寸标准。
2. 点击 **检测并高亮候选**。红点尚未删除；可切换“全部点／选中点”取景，或点 **原图定位**，在实际分割图像网格中检查位置。IR 使用原生 IR，RGB 使用分割时的校正 RGB；不拿点云投回原始 RGB 的检查图代替分割底图。原图或掩码无法校验时说明原因，三维清理仍可使用。
3. 可选“邻域稀疏的点”。它按近似 kNN 的第 k 个邻居距离提出候选，阈值为物理下限与稳健统计上限中的较大值；默认 k=8、物理下限 50 mm。RGB 对齐网格密度不代表独立测量密度，参数需按相机与路线试验。所有检测均不自动删除，轮廓和端点处须人工核对。
4. **框选删除／框选恢复** 在完整点云上计算，贯穿当前视角前后所有深度；预览抽样不参与选点。可连续拖出多个矩形，选区累加且重叠点只计一次；按住 **Alt 拖动旋转**、**Shift 拖动平移**，核对后点击 **确认删除／恢复选中点**。确认后仍保持框选模式，可继续下一轮；**Esc** 或再次点击当前框选按钮退出模式，已选点保留；**取消选点** 清空累计选区。切换删除／恢复后，下一次框选开始对应操作的新选区。显示已删点时用灰色标识。
5. 修改自动暂存，可 **撤销／重做／恢复全部**，关闭、重启后仍可恢复操作历史。“重新载入”会重读已暂存版本；尚未确认的候选不保存。拖动旋转、滚轮缩放、Shift 拖动平移。

清理工具采用连续单列布局，检测方式与检测按钮同行，三个参数并排，框选、确认和历史操作依次排列。工具面板缩窄以扩大点云视野；较短或较窄窗口可滚动查看。

清理只排除点，不平滑、补洞、改变毫米尺度或改写原点。原始点云、已确认分割和原始采集均不改写。点索引绑定原始 `points.npz` 与 `pointcloud.json` 的哈希；源点云变化或记录损坏时拒绝套用旧清理。清理和测量记录暂存在工作台 `.state/processing_cache`，使用顶部 **导出点云成果** 导出完整成果。

### 对齐后按区域或逐片复核

1. 使用现有 **坐标对齐** 功能确认地面、尾根与颈根，再进入 **测量复核**；进入后自动使用猪体坐标并载入切片。未确认对齐时，页面提示先对齐且禁用测量工具。删点不会修改已确认的坐标矩阵；同次采集可继续复用参考。
2. 默认沿可见中心线等弧长取 32 个局部法向剖面，薄带 20 mm，最少点数 20；可改为 16/64 个剖面及其他参数。修改后点击 **计算并保存参数**。
3. 滑动或逐片切换，在三维橙色带、横向/Z 剖面及 **原图定位** 中检查同一个剖面的可见边界。可在序列曲线上拖选区域，或输入起止编号，点 **确认所选／淘汰所选／恢复待定**；点 **全部剖面** 可一次处理整条序列。批量确认跳过无法计算宽度的剖面并提示数量，切换当前片会保留选区。也可单片标记 **边界完整·可测／缺失·不可测／待定**。
4. 宽度使用局部法向横向坐标的 P02–P98 投影跨度；可见横剖面弧长累计横向分箱中位数折线，缺箱、稀疏箱或明显高度跳变时留空。它不是完整围度。序列包含 10 个通道，具体定义见 [几何特征说明](features.md)。
5. 左侧和右侧都显示同一组确认进度，例如 3/32 片。全部剖面确认为可测、使用已确认对齐的端点且中心线有完整支撑时，汇总标记“测量已复核”；各通道缺失仍单独记录。端点与地面默认可用，不适用时修正坐标对齐或用顶部阶段筛选淘汰采集。
6. 改变剖面参数，执行删点／恢复或更换坐标参考后，需要重新确认剖面。旧参考条件选项不再使用；旧直线切片入口已移除，历史记录保留但不计入当前剖面进度。原始深度有效率不因删点改记为 100%。

“点云清理”和“测量复核”均使用当前清理版本；没有清理记录时使用原始点云。顶部按钮会随页签显示**清理筛选／对齐筛选／测量筛选**，各自记录保留、待定、淘汰：保留表示该阶段继续采用，待定表示暂缓，淘汰会停止本采集的后续阶段。左侧各阶段文字分别显示为绿色、黄色、红色，被前序淘汰阻断的后序也显示红色。后序淘汰不撤销前序保留，前序改回保留／待定后可继续后续处理。逐片可测／不可测与阶段筛选分别记录。

点集变化会使相关阶段回到待定；改变坐标参考只影响对齐和测量，不影响清理筛选；改变测量参数或剖面状态只影响测量筛选。撤销回完全相同的版本时可恢复对应结论。旧共享筛选记录仅恢复到能由版本识别的阶段：无坐标参考的记录归清理，有坐标参考的归对齐；不能识别的旧记录留待确认。读取不会重写原记录。

顶部 **导出点云成果** 可分别勾选**点云清理／坐标对齐／测量复核**，默认全选。只做清理即可导出清理；做完清理和对齐即可一起导出两项；后序未处理不会阻止前序导出。已保存参数或逐片复核的测量阶段自动包含 `geometry_features.json`（全部 13 项整体几何指标及单位、有效性和复核标记）、`profile_sequence.csv`、`profile_sequence.npz` 和 `measurement_summary.json`。批量 `geometry_features.csv` 在拆分模式中只保存在“测量复核”目录，合并模式中保存在根目录，不用逐条下载；部分复核也可导出并保留待定及缺失掩码。导出弹窗保留阶段数量与保存设置，不再展开目录和文件清单。单纯确认坐标或删点不会自动产生测量阶段。

选择当前／已勾选／全部采集，分别勾选要导出的阶段状态；默认包含保留、待定、淘汰。原“采集范围条件”选择已移除，未对齐采集也可导出已有清理成果。前序淘汰后的阶段不输出，即使过去有历史文件。拆分目录按各自阶段状态归类，合并目录按**本次导出的最后一个阶段状态**归类，`workflow_stages.json` 和批量 `stage_screening.json/csv` 列出每阶段的独立状态和成果路径。例如清理保留、对齐淘汰，勾选保留与淘汰可导出这两项；仅勾选保留仍可导出清理。拆分时仅保存该阶段产品及轻量来源记录；合并时保留计算及继续编辑所需的原始点集、清理索引和坐标参考。

拆分模式的固定文件名和内容见下方“文件夹组织”。以下主文件规则适用于生成成果及合并导出。仅清理使用相机坐标，包含对齐或测量成果时使用猪体坐标；清理的相机坐标文件仍可通过阶段清单独立找到：

| 当前处理情况 | 主 PLY | 主 NPZ | 坐标系 |
| --- | --- | --- | --- |
| 无处理记录、未对齐 | 生成时的 IR／RGB PLY | points.npz | 相机 |
| 有处理记录、未对齐 | cloud_cleaned_mm.ply | cleaned_points.npz | 相机 |
| 无处理记录、已对齐 | cloud_body_mm.ply | body_points.npz | 猪体 |
| 有处理记录、已对齐 | cloud_cleaned_body_mm.ply | cleaned_body_points.npz | 猪体 |

清理／复核共用处理记录，因此尚未删点但已保存剖面参数或复核状态时，处理后文件仍包含全部原始点。上述 NPZ 和 PLY 均使用完整点集，不是画面抽样。原始生成文件与本次所选阶段所需的清理／对齐历史作为追溯资料一并保存；每条 `current_pointcloud.json`、根清单 `pointcloud_dataset.json` 的 `primary_ply/primary_npz` 以及整批 `cloud_screening.json/csv` 统一记录当前主文件、坐标和测量复核状态。`pointcloud.json` 继续描述原始生成数据。保留目录中的未复核数据仍明确标为 `measurement_ready: false`，不能把保留目录当作全部特征已验收的集合。

合并导出保留全部原始成果，并增加：

```text
pointcloud_cleaning.json    # 原始文件哈希、清理规则、历史及剖面确认记录
point_edits.npz             # 全量原始点索引、删点掩码与撤销历史
cleaned_points.npz          # 清理后相机坐标，含 source_point_index
cloud_cleaned_mm.ply        # 清理后相机坐标 PLY
cleaned_body_points.npz     # 已对齐时：同一批保留点的猪体坐标
cloud_cleaned_body_mm.ply   # 已对齐时：猪体坐标 PLY
profile_sequence.csv/npz   # 已对齐时：10 通道剖面序列及有效性、可用性和复核标记
measurement_summary.json  # 当前局部法向剖面确认进度与对齐参考条件
processing_preview.html   # 可离线打开的只读清理与测量预览
```

所有逐点属性随同一索引一起筛选，`source_point_index` 始终指向不可变原始 `points.npz` 的行。完整合并导出重新打开后仍可撤销清理；离线 HTML 只读，编辑需回到工作台。精简阶段包不包含完整原始点集和撤销历史，继续编辑时打开原工程或完整合并导出。

## 地面与猪体坐标对齐

生成或打开点云成果，选择一次采集，点击查看器上方的 **坐标对齐** 页签。直接在主工作台内按原生深度网格标注，
适用于双目／iToF，以及 IR／RGB 两种分割路线。RGB 点云先投影回原生深度网格供标注复核，
不会把 RGB 掩码缩放成 IR 掩码，也不会重复应用 RGB 外参。

1. 如果原始数据已搬家，在对齐页选择**原始采集根目录**。程序按相对目录匹配，并核对原始深度和
   `reconstruction.json` 的 SHA-256；仅有躯干 PLY 无法恢复地面参考。
2. 默认使用 **RGB 场景＋猪体点云范围**，在同一片可见地面点击至少 3 个顶点，形成闭合区域。
   RGB 通过同次采集的内外参和完整原始深度映射到原生深度网格，并核对源图哈希、时间戳、
   镜像和翻转状态；没有有效映射的区域显示灰色棋盘格，不填补深度或补造背景。
   RGB 缺失、不同步或无法核对时，自动切换增强 IR（IR 无法核对时使用增强深度灰度），并显示原因。
   还可切换原始 IR／深度伪彩色，调节显示亮度，或关闭绿色范围叠加；切换保留同一套标注。
   IR 增强只用于显示，使用对数压缩、局部对比增强和暗部提亮，不能恢复没有信号的纹理。
   避开猪体、栏杆、墙面、深度空洞。绿色为当前点云的投影范围，不代表分割已通过审核。
   RGB 可见性只依据深度相机观测到的场景；RGB 视角独有遮挡物仍需人工核对。
3. 分别点击**标记尾根**、**标记颈根**，按统一躯干切割口径选择中点。无深度或与猪体点云明显
   不一致的端点会被拒绝。尚未覆盖颈根的局部点云需要先复核分割。
4. 点击**计算并预览对齐**，检查三维地面网格、XYZ 方向、端点，以及原始场景叠加图。
   检查图采用计算时选用的场景图与亮度，显示方式写入 `alignment.json`，不改变地面拟合的深度点。
   核对地面、端点与坐标方向后，点击上方**确认坐标对齐**。对齐成果持久保存，采集筛选结论单独确认，不再逐项勾选核对框，不弹出保存目录；保存失败会撤回本次改动。
   可直接切换下一条；刷新、重启服务或重新打开原成果目录后，已确认记录与预览都能恢复。

采集信息、点云清理／坐标对齐／测量复核页签与质量筛选合并为一行。左侧标注、右侧预览按窗口高度显示，标注工具合并以扩大图片区域。默认放大猪体附近，可滚轮缩放，选择“移动”、按住空格或鼠标中键拖动；“全景”恢复完整场景，“猪体”重新定位。所有标注仍换算为原生深度像素，视图缩放不改变拟合或导出尺寸。

采集标题旁的**清理筛选／对齐筛选／测量筛选**评价当前页签阶段，三个结论分别保存。筛选按钮默认待定，确认对齐只保存坐标参考，不会自动设为保留。左侧同时列出三项状态；前序淘汰时后序显示“已停止”，对应页签禁用；返回前序修改筛选结论可恢复处理。

对齐页可勾选 **自动切换下一条**：确认对齐或保存当前阶段筛选后，切换到当前范围后面的待对齐采集，跳过已对齐、前序淘汰及对齐淘汰项；选项默认关闭并记住上次选择。清理和复核页可继续操作当前点集及逐片结果。

确认后的对齐暂存于 `.state/alignment_cache`，清理和测量暂存于 `.state/processing_cache`，刷新、重启或重开原点云根目录均可恢复。导出只创建新的成果副本，不会将部分导出替换为工作台的完整编辑数据。使用顶部 **导出点云成果** 选择阶段、采集和筛选状态，设置一次目录后统一导出。`cloud_screening.json/csv` 描述导出副本的主点云和测量状态；`stage_screening.json/csv` 逐阶段列出实际导出情况。清单使用 `relative_dir` 保存原采集身份，`storage_relative_dir` 保存实际存储路径。导出弹窗的 **文件夹组织** 提供两种方式：

- **按阶段拆分文件夹**（默认）：每个阶段仅保存自身产品和轻量来源／筛选清单，不复制原始点云、检查图、预览点数据或撤销历史。清理阶段为当前保留点的相机坐标 `cloud_cleaned_mm.ply`、`cleaned_points.npz` 和清理摘要；对齐阶段为同批保留点的猪体坐标 `cloud_body_mm.ply`、`body_points.npz` 和 `alignment.json`；测量阶段为几何 JSON、剖面 CSV／NPZ 和复核汇总，阶段根目录另有批量几何 CSV。未删点时清理产品包含完整原始点集。各阶段按自己的保留／待定／淘汰分类，只建立有成果的阶段目录。
- **按采集合并存放**：同一采集的所选阶段共用一个完整目录，按最后导出阶段的状态分类，保留原始文件、处理历史和离线预览，可重新打开继续编辑。可继续独立勾选任意阶段。

例如拆分模式中，同一采集可位于 `点云清理/保留/pig_编号/采集时间`、`坐标对齐/保留/pig_编号/采集时间` 和 `测量复核/待定/pig_编号/采集时间`。每条 `stage_result.json` 标明阶段、坐标、成果文件和来源哈希，`workflow_stages.json` 记录结论及版本。精简包供交付和分析，继续清理或撤销需打开原工程或完整合并导出；工作台会对新精简包给出明确提示。此前版本导出的完整拆分包仍可按原方式重新打开。

坐标定义：原点为尾根在拟合地面的投影；X 沿地面从尾根指向颈根；Z 为地面法线、指向猪体；
Y = Z × X，按右手规则指向猪体左侧。变换仅旋转和平移，保持 mm，不缩放、不拉直躯干、不补全遮挡面。
地面为局部拟合参考；只有地面水平时，Z 才能解释为竖直高度。

地面使用固定随机种子的 RANSAC 和内点重拟合。初始容差 10 mm，可调整为 1–30 mm；
至少要求 100 个有效点、60% 一致内点，以及两个方向约 80 mm 以上的支撑范围。
这些是可用性检查参数，拟合 RMS／95% 分位残差并不是相机实际测量误差，仍需结合检查图和实物验证。
算法无法仅凭平面拟合证明选中的是地面，因此需要人工核对。

确认后的坐标参考按**同次采集的原始深度与重建记录哈希**缓存，不依赖分割方式、文件夹位置或点数。
切换到同次采集的另一套 IR／RGB 点云，可点击**复用同次采集已确认坐标**，保持完全相同的矩阵。
也可从已打开的完整对齐成果恢复参考。不同采集分别建立参考，不把不同时间的猪体刚性拼接。

直接保存的对齐成果是新的完整文件夹，原始采集、分割和已有相机点云不改写。
除了原相机点云副本，还包含：

```text
采集目录/
├── body_points.npz       # xyz_mm 改为猪体坐标；其余逐点属性保留，增加 source_point_index
├── cloud_body_mm.ply     # 猪体坐标 XYZ + 配色，单位 mm
├── alignment.json       # 平面、端点、坐标轴、正/逆 4×4 矩阵、哈希、质量、确认与参考编号
├── alignment_check.png  # 原生网格中的地面内点、端点与 250 mm 坐标轴
├── body_preview.html    # 可离线查看的猪体坐标预览
└── cloud_review.json    # 点云保留／待定／淘汰状态，绑定原始点云、清理点集与坐标参考
```

`alignment.json.frame.camera_to_body_4x4` 使用列向量约定：`[p_body,1] = T @ [p_camera,1]`。
NumPy 行数组相应使用 `xyz_body = xyz_camera @ T[:3,:3].T + T[:3,3]`。
`body_to_camera_4x4` 为逆变换；原 `points.npz` 仍保留原生深度相机 XYZ。
两套 NPZ 的行对应一致。坐标确认独立于 `segmentation_reviewed`，不会把初稿标成已审核分割。
点云筛选首先写入工作台设置，保存或导出新成果时附带 `cloud_review.json`，换电脑后打开新成果也能恢复状态。

确认后点击**查看已确认的猪体坐标点云**，默认显示猪体坐标；可在**相机坐标／猪体坐标**之间切换。
已有“按文件夹导出”会一并保留对齐文件。缺少完整对齐文件或 NPZ 校验不符时，不显示为已对齐成果。

## 输出

生成点云与合并导出沿用下方单份采集结构；合并导出会增加状态分类层。按阶段拆分时，精简产品放在“阶段／状态／原采集路径”，总目录和各阶段目录均附成果清单，测量阶段另有批量几何表；不套用下方完整副本文件列表。

```text
输出目录/
├── index.html
├── pointcloud_dataset.json       # 浏览器生成/导出的采集清单
├── export.json                   # 浏览器任务结果；CLI 使用 summary.json
├── cloud_screening.json          # 统一导出：本次范围内全部点云筛选记录
├── cloud_screening.csv           # 同上，可直接查看保留／待定／淘汰及导出情况
└── pig_编号/采集时间/
    ├── cloud_rgb_mm.ply           # RGB 分割时生成；全密度 XYZ + RGB
    │                             # 每次采集的 PLY 为二者之一
    ├── cloud_ir_mm.ply            # IR 分割时生成；全密度 XYZ + 红外强度配色
    ├── points.npz                # 完整点属性，无 pickle
    ├── pointcloud.json            # 坐标、单位、标定、来源校验值、质量记录
    ├── mask_depth_check.png       # 绿色为掩码，红色为无有效点的掩码像素
    ├── rgb_projection_check.png   # 绿色标出目标点映射到原始 RGB 的位置
    ├── rgb_registration_check.png # RGB 且有原始深度时：青色深度边缘、黄色掩码边界
    └── preview.html              # 离线交互预览，不需要外部网络
```

NPZ 数组按行一一对应：`xyz_mm[N,3]`、`pixel_uv[N,2]`（u 列、v 行）、`depth_code[N]`、`infrared_raw[N]`、`infrared_valid[N]`、`rgb[N,3]`、`rgb_valid[N]`、`rgb_uv[N,2]`、`depth_discontinuity[N]`。旧版 IR NPZ 未单列 `infrared_valid`；新生成的 IR 数据为 true，未关联 IR 的 RGB 数据为 false。其中 `rgb_uv` 越界／缺失可以是 NaN，应结合 `rgb_valid` 使用。

PLY 为二进制 little-endian，坐标是 float32 毫米，还保存 u/v、IR 值及 RGB 有效标记。很多查看软件只显示 XYZ/RGB，需要在软件中按毫米解释尺度；用 NPZ 可保留全部属性。

掩码内零深度与求逆不收敛的射线会被排除。没有平滑、补洞、自动裁掉边缘、最远点采样或按每只猪缩放。4 邻域出现超过 50 mm 深度差的点仅标记为跳变候选，供后续检查，不直接认定为飞点删除。

质量统计中的有效率分母是原始掩码像素数量。X/Y/Z 轴向跨度是当前姿态的包围盒跨度，不能作为完整体长、体宽、体高或真实体积。单视角只保留可见表面。

源图像和分割目录只读。程序核对分割阶段的源文件 SHA-256，检查原始深度码与分割使用的毫米数组一致，处理前后再次核对读取文件、掩码及分割 JSON。点云输出与源数据／分割目录不得相同或互相包含。

## 验证

目录核对按采集逐项进行：缺少分割记录、JSON 损坏、输入模式不一致或缺少文件时，
该采集显示为“核对失败／自动跳过”，其余采集仍可载入、生成。左侧可筛选核对失败项，
“查看／标记”打开逐项原因；也可对当前采集手动标记跳过或取消标记。
标记只写入工作台 `.state/settings.json`，按原始目录和分割目录组合保存，不改写分割审核状态。
取消手动标记不会绕过失败核对；修复源文件后应重新核对载入。

生成时仍逐帧核对深度、标定和来源校验值。单帧失败会记录原因并继续后续采集，
完整成果仍按原目录层级发布。生成成果根目录另含 `input_validation.json`，
记录当前输入的失败项和手动跳过标记；页面也支持下载核对记录。

```sh
python3 -m unittest discover -s pointcloud_workbench/tests -v
node --test pointcloud_workbench/tests/test_workbench.cjs
```

测试涵盖真实尺度、非整数毫米换算、强畸变求逆、独立正向重投影、RGB 遮挡和越界、外参只应用一次、分割确认门槛、不同步 RGB 保留几何、源数据变更拒绝、二进制 PLY／NPZ 与路径保护。还需以你的实测标定物验证实际测量误差。
